# GenDesk 生图投单

把提示词 + 参考图写成一份**工单目录**丢进 GenDesk 的收件目录。GenDesk 会在 2 秒内
自动导入提示词与参考图、建批次、开始生成。

**你不生成图片，也不碰 GenDesk 的库。** 你只写文件。导入、编号发放、建批、调度、
重试、验收全在 GenDesk 里——那些不是智能任务，而且业务真相只能有一处。

> 写新的 `prompts-*` skill 时，不要引用本 skill，直接把同目录下
> `标准产出规范.md` 的「最后一步」抄进那个 skill 的收尾。少一次跳转就少一次遗漏。

## 什么时候用

用户在同一轮里给了参考图（`@` 引用或拖入文件）并要你写生图提示词。提示词写完就该投单——
而不是把文档交给用户、让他再去软件里手动导入两次。

## 四步

```bash
JOB=~/GenDesk交接/生图/收件/$(date +%Y%m%d)-<产品>-<题材>
mkdir -p "$JOB/images"
cp <参考图原路径> "$JOB/images/"        # 拷贝，别移动别软链
```

2. Write `$JOB/提示词.txt`（格式见下）
3. 可选：Write `$JOB/说明.md`（方向地图/可替换变量表，给人看的）
4. **最后**：

```bash
printf ok > "$JOB/READY.txt"
pgrep -x GenDesk >/dev/null || open -a GenDesk
sleep 3; cat "$JOB"/{结果,待确认,错误}.txt 2>/dev/null || true
```

把回执内容念给用户听（建了哪些批次、多少张、实际发出去哪些参数）。

**`READY.txt` 必须最后写**：没有它的目录 GenDesk 一律不碰，否则可能在图还没拷完时就开始导入。

**进程检测必须用 `pgrep -x`**：`-f` 会匹配到路径里带 "GenDesk" 的 node/vite 进程，
在开发机上「看起来能用」其实一直在说谎。

## 提示词.txt

```
分组: 黄色系卡套
前缀: KT
参考图: images/黄A.jpg, images/黄B.jpg
比例: 3:4
抽卡: 1
用途: 图生视频

（第一条完整提示词，一整段）

（第二条完整提示词……）

分组: 蓝色系卡套
参考图: images/蓝.jpg
比例: 9:16

（……）
```

- 组头 `键: 值` 紧跟 `分组:`；正文每条独立成段、条间空一行、不加编号。
- 组头**只在该组第一条正文之前生效**，所以正文里的「比例：3:4 的构图……」不会被吃掉。
- 键：`分组`(必填) · `参考图`(多组必填) · `前缀` · `比例` · `尺寸` · `格式` · `抽卡` · `用途` · `场景` · `标签`。

## 四个坑

1. **正文里写「9:16」对模型不构成约束**——那是描述不是参数。要竖幅就写 `比例: 9:16`。
2. **`尺寸:` 两边边长必须是 16 的倍数**（`1080x1920` 会被拒，1080 不是；`1536x2048` 可以）。比例交给 `比例:` 最稳。
3. **多组必须逐组写 `参考图:`**，GenDesk 不按顺序猜——猜错要到验收时才看得出来。单组时可省（`images/` 全部图挂给它）。
4. **各组比例不同会自动拆成多个批次**（参数是批次级的）。这是正确行为。

任务数 = Σ(每组条数 × 该组挂靠图数 × 抽卡)，**不是笛卡尔积**。

## 超阈值 / 失败

超过设置里的上限（默认 500 张）→ GenDesk **什么都不导入**，写一份 `待确认.txt`。
把里面的数字念给用户，问要不要跑；**不要自作主张创建 `确认.txt`**——阈值存在的意义
就是让人看一眼。用户同意后 `touch "$JOB/确认.txt"` 即可，或让他在设置页点「确认开跑」。

失败 → 工单留在原地 + `错误.txt`。整单要么全生效要么全不发生，库里不会留半份。
改好后让用户在设置页点「重试」，或换个工单目录名重投。

## 边界

- 不要用 `osascript` 去点 GenDesk 界面，不要直接读写它的 SQLite。
- 不要替用户决定要不要花钱跑一批。
- 验收在 GenDesk 的验收页人工完成，这一步不该被自动化。
