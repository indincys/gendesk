# GenDesk 图生视频 · 提示词改写

> **v1.1**（2026-07-29）。改了规范就升版，并在同目录 `CHANGELOG.md` 记一条。

你唯一的任务：把 GenDesk 验收通过的**生图**提示词，改写成**图生视频**提示词，写回交接目录。

**不要调 `dreamina`。** 提交、轮询、下载、重试、验收全部在 GenDesk 里，它有状态机、
崩溃恢复和看板。你在这条链上负责的是唯一机器替代不了的那一步。

## 零输入起步

固定路径（GenDesk 设置页「图生视频 · 交接目录」可改，默认就是这个）：

```
~/GenDesk交接/v2v/待改写/index.jsonl      ← 从这里起步，一行一个待改写的组
~/GenDesk交接/v2v/待改写/<组>/manifest.jsonl
~/GenDesk交接/v2v/待改写/<组>/thumbs/W123.jpg
~/GenDesk交接/v2v/待改写/<组>/READY.txt    ← 只处理有它的组目录
~/GenDesk交接/v2v/已改写/<组>/rewrite.jsonl ← 你写这里
```

流程：

1. 读 `待改写/index.jsonl`。为空 → 告诉用户队列是空的，结束。
2. **逐组处理**，一组一个 `rewrite.jsonl`。不要跨组混改 —— 同组分镜最后要剪进同一条成片，
   运镜语言与时长必须统一，跨组混着改风格会飘。
3. 每组：`head -n 1` 起逐行读 `manifest.jsonl`（JSONL，可 grep、可分片，不必整包读进上下文），
   看 `thumbs/` 里对应的缩略图，写出视频提示词。
4. 写 `已改写/<同名组目录>/rewrite.jsonl`。GenDesk 监听该目录，2 秒防抖后自动收录，
   条目进「待提交」列。
5. 告诉用户：改了几组几条，去 GenDesk 视频流水线页的「待提交」列过目并提交。

组目录名对同一组是**恒定**的，写回时用与工单侧完全一样的目录名。

## 回写格式

一行一条 JSON：

```json
{"id":"W123","videoPrompt":"首帧自然延续：…"}
```

可选字段 `modelVersion` / `duration` / `videoResolution` —— 只在你对**这一条**有具体判断时给
（比如动势大给 8 秒）。GenDesk 会尊重它，优先于设置里的全局默认值。不确定就别给。

**`id` 必须原样回传** manifest 里那个 `W…`。不要按文件名匹配：GenDesk 的输出文件名里编号
已去连字符，`BR140010` 反推不出是 `BR14-0010` 还是 `BR1-40010`，文件名本来就不可逆。

## manifest 字段怎么用

- `thumb` —— **先看图**。提示词描述的是意图，图才是即梦真正会拿到的首帧。
- `variablePart` —— 剥掉组内公共前后缀后的可变部分（场景 / 构图 / 动势）。这是改写的主要素材。
- `sourcePrompt` —— 生图提示词全文。剥离只是提示不是契约：拿不准、或 `variablePart` 读起来
  缺上下文时，回读全文。
- `strippedPrefixChars` / `strippedSuffixChars` —— 被剥掉多少字。数字大说明该组共享一段很长的
  产品保真模板（实测有 147–384 字的），那段对图生视频是噪音甚至有害：图已经是首帧、产品已经
  画对了，再喂 300 字配件穿接关系只会把改写带偏。但**它列出的那些配件你仍然需要知道**，
  因为「产品锁定」那一句要逐项点名 —— 从缩略图和 `sourcePrompt` 里取。

# 改写规范

生图提示词说的是「画成什么样」，视频提示词说的是「从这一帧开始怎么动」。两者不是同一件事，
不要顺手把生图提示词加几个动词就交。

## 官方公式（Seedance / 即梦）

> 主体 + 运动 + 环境（非必须）+ 运镜/切镜（非必须）+ 美学描述（非必须）

**图生视频要略掉「主体」与「环境」的外观描写**——首帧图已经把主体、场景、风格全定死了，
重复描述只会挤占模型对「怎么动」的注意力。所以我们实际只写三段：**运动 + 运镜 + 约束**。

官方基础原则，逐条都用得上：

- **给出主体、运动的限定描述**，不要只说「动起来」。
- **善用程度副词**：极缓、缓慢、轻微、连续不停顿。这是控制幅度的唯一手段。
- **用特征指定主体，且指定方式全程一致**。同一个东西前后必须用同一个称呼——
  一会儿「挂绳」一会儿「弹簧绳」，模型可能当成两个物件，于是一个静止一个乱动。

官方**运镜描述公式**：起幅构图描述 + 运镜 + 运镜幅度 + 落幅构图描述。
官方运镜词表（只用这些词，别自创）：**推 / 拉 / 摇 / 移 / 跟 / 升 / 降 / 甩 / 环绕 / 旋转 / 变焦**。
本项目只用其中的**移**（极缓平移），落幅景别与首帧保持一致。
官方景别语法是「主体 + 景别」：`桌面的中景`、`过道的远景`（不是「中景桌面」）。

## 动静分层：这是本项目的核心规则

一条视频里，画面元素分两类，**写法完全不同**：

**可以动的（真实场景元素）** —— 让画面活起来的就是它们，是「真实感」的来源：

- 人物、宠物、路人、手 —— 可以移动、走动、变换姿态
- 背景事物 —— 门帘、树影、窗外车流、蒸汽、浮尘
- 光影 —— 明暗交界线游移、光斑掠过、天光明暗呼吸
- 机位 —— 极缓平移 / 焦点转移。景别保持首帧的景别，产品在画面里的大小不变

**必须锁死的（产品本体）** —— 卡套、挂绳、扣环、铃铛、钥匙圈、龙虾扣等：

- 默认**完全静止**；最多允许**轻微缓慢移动**（如挂绳随风微摆）
- **任何情况下不得形变**：不改变形状、结构、比例、材质、图案、配件的穿接关系
- 这一条比什么都重要。即梦对小配件的结构记忆很弱，不点名就会自己「重新设计」一遍

产品那句用官方广告示例的句式最稳：**保持形状、比例与材质真实一致，不新增无关元素**。
配件要**逐项点名**——「卡套与黄色弹簧挂绳、银色与黄色龙虾扣、分裂环、橙黄色铃铛、
两枚五角星扣环完全静止」——这一句比任何形容词都管用。

允许局部动、整体不动时，用官方那种写法把范围划清楚：
「挂绳末端随微风轻动，但卡套本体与所有扣环保持首帧原样」。

## 观感目标：手机随手拍

成片要像**人随手拍的**，不是商业广告。两句话到位：

- **「拍摄时带着轻微手持的呼吸感」**（官方术语，比自造的「手持微抖」响应更准）
- **「延续手机实拍的真实质感」**（收尾，防它切成打光精致的电商广告调）

官方明确说过「写上视频类型控制画面特征」——这两句就是在指定视频类型。

## 景别保持首帧的景别

官方运镜公式里的「落幅构图」，在本项目一律等于起幅：**产品在画面里的大小自始至终不变**。
产品被放大多少，即梦就要重绘多少像素，而它对卡套图案与扣环的结构记忆很弱——放大即改样。
所以运镜只写「镜头固定不动」或极缓平移，画面的活气交给场景元素（人影、光斑、门帘）去出。

## 不要切镜

即梦靠「切镜 / 镜头二 / 镜头切换」这类词触发分镜。B-Roll 素材要的是一镜到底，
所以：**不用任何切镜词汇**，并在约束里写明**画面稳定、无切镜**。

## 成稿结构

按顺序写四段，中文，**150–250 字**（官方上限约 500 字符；短了约束不住，长了模型会挑着看）：

1. **开头固定写「首帧自然延续：」** —— 明确这是延续而不是重新构图。
2. **运动**：场景里那一到两处动作，按发生的时序写，逐个加程度副词限定幅度。
3. **运镜**：默认「镜头固定不动」；要动就「镜头极缓地向左平移，只此一个运镜动作」。
   **运镜只给一种**，并说明幅度。加上手持呼吸感那句。
4. **约束**：产品逐项点名静止 + 不形变 + 构图/色彩/光线与首帧一致 + **景别与首帧一致** +
   「自始至终只有首帧已有的物体」（防它自己加东西）+ 无切镜 + 手机实拍质感。

## 范例

**背景人物动、镜头不动**（用户实拍验收通过）：

> 首帧自然延续：画面深处过道方向那团虚化的人影极缓地横向移动、缓缓走出画面，始终虚化模糊、
> 不进入景深，幅度轻微、连续不停顿。镜头固定不动，带轻微手持的呼吸感。卡套与黄色弹簧挂绳、
> 银色与黄色龙虾扣、分裂环、橙黄色铃铛、两枚五角星扣环完全静止，形状、比例与图案保持首帧原样、
> 不发生任何形变；构图、色彩与光线与首帧一致，画面稳定无切镜，自始至终只有首帧已有的物体，
> 延续手机实拍的真实质感。

**只让光动、万物静止**：

> 首帧自然延续：窗外透进的光斑在桌面上极缓地横向移动、明暗轻微起伏，连续不停顿，不扫过卡套
> 本体。镜头固定不动，景别与首帧一致，带轻微手持的呼吸感。卡套与银色金属圆环、绿色龙虾扣、
> 绿色铃铛、两枚五角星扣环、绿色弹簧螺旋挂绳完全静止，桌沿探过来的短毛猫、玻璃杯与帆布收纳袋
> 也保持不动，形状、比例与图案保持首帧原样、不发生形变；画面构图与色彩与首帧保持一致，
> 画面稳定无切镜，自始至终只有首帧已有的物体，延续手机实拍的真实质感。

注意第二条里那只猫：**它出现在画面里但被要求不动**。可动的元素不是必须动——
当它紧贴产品、一动就会牵动构图时，锁住它更安全。看图判断。

## 反面清单（写出来就是错的）

- ❌ 产品自己动：「卡套缓缓旋转展示」「挂绳被拿起」—— 必然形变。
- ❌ 没点名配件：只写「卡套保持静止」，铃铛和扣环就会被重新设计。
- ❌ 把产品拍大：「镜头极缓地向卡套推近」「变焦放大到铃铛」—— 产品一放大就被重画。
- ❌ 堆运镜：「镜头平移同时环绕并上摇」—— 三个都做不好。一条只给一种运镜。
- ❌ 切镜词：「镜头切换到特写」—— 4 秒里切镜等于两个都没拍好。
- ❌ 商业广告词：「高级质感」「大片氛围」「电影级打光」—— 直接毁掉手机实拍的真实感。
- ❌ 加东西：不写「只有首帧已有的物体」，它就会自己添一杯咖啡。
- ❌ 照抄生图提示词里的产品保真模板（那 300 字配件穿接关系）—— 图已经画对了，
  再喂一遍只会把改写挤偏。

## 不要做的事

- 不要调 `dreamina`（任何子命令）。
- 不要写 `rewrite.jsonl` 以外的文件，不要改 `manifest.jsonl`，不要动 `待改写/` 下的任何东西。
- 不要跳过看图。只读文字改出来的提示词经常和实际首帧对不上。
- 一条也别漏：manifest 有几行，`rewrite.jsonl` 就该有几行。漏掉的那条会一直卡在「待改写」列。
