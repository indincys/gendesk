# Poster 图片接入

GenDesk 适配 Poster 的通用 CLI：`poster.images/1`（`export-image-products` / `import-images`）收图，`poster.image-sets/1`（`import-image-sets`，每项直接带图）组图文，不写对方 SQLite。Poster 不保存明星名单或生成工具约定，也没有为 GenDesk 写的特例；接口规范在 Poster 项目的 `docs/协作规范/图片库CLI接入规范.md` 与 `内容导入CLI接入规范.md`，权威字段表用 `poster import-spec image-sets` 读。

## 使用

设置 › 审稿后自动化 › **自动导入 Poster**，默认关闭，手动打开。打开后：

1. 审图页通过的图（单张、所选或本组，怎么点都一样）按「组」组成 Poster 里的**一条图文**（图片包），在后台导入，**不弹窗、不确认**，不拉起 Poster 界面、不自动发布。见下文「图片包」。
2. 图文按款式进入 Poster 对应商品，商品图片库里也能看到这些图（按原定类型，见下文「库位」）；标题、正文在 Poster 里配：入库时 Poster 先从这个商品的文案库自动配，配不上就在「待发」里显示「缺标题」，点开补上。
3. 需求名（或 `posterType`）是封面的图不组图文，照旧每次通过登记一个批次，进封面库。
4. 同时打开「自动转实况图」时，批次先等实况图配对落盘（JPG + MOV），再连同视频一起导入；某张实况转换失败则批次标「需处理」并写明原因，不会只导一半。实况导入要求 Poster 声明 `live-photo` 能力，旧版 Poster 会明确报错。

关闭开关只暂停新批次与后台导入，已导入图片和已有记录保留。升级前遗留的「待确认」批次在 0050 迁移时一律标为跳过，不会被自动导入。

## 归属

- 每个 `(sku, style)` 解析成 Poster 商品 ID 的顺序：已保存的绑定 → 20 位明星的完整「姓名日历（2027）」唯一匹配。新工单的 sku 为空时取 `organization.product`，即 `(产品, 款式)`。明星身份来自 sku 的完整别名（`姓名日历`、`姓名日历（2027）`、`calendar-2027-拼音`），或产品为 `2027明星日历`（兼容旧写法 `明星日历2027`）时款式正好是 `姓名` / `姓名款`。不从图片文件名或数字 SKU 猜身份，不按前缀或模糊匹配（`谢霆锋演唱会款` 需绑定一次）、不新建商品。
- **投单前就检查**：开启自动导入时，`gendesk submit` 收录前按同一规则检查每个款式，对不上就让工单停在待确认、不生图；Agent 在用户确认商品后用 `gendesk poster bind` 保存绑定再 confirm。读不到 Poster 时不拦单。
- 解析不出的款式让整批停在「需处理」，原因写进批次。设置页「指定商品」或 `gendesk poster bind` 选一次即保存绑定并开始导入，同款其他「需处理」批次一并续导，之后同款自动导入；也可「不导入」结束这一批（不影响已通过的审稿）。
- 绑定存的是商品 ID：商品改显示名仍沿用；原商品被删时不自动认领同名新商品。
- 图片里的人是否正确由人工审稿确认，元数据匹配不能代替看图。

## 图片包

一组 = **同一次提交（GenDesk 批次）× 同一款式 × 同一需求**（Agent 显式写了 `posterType` 时按它）。同一套背景一起生成的图天然是一套；一次提交给好几个款式生图时，每个款式各成一条图文、进各自的商品。审稿页「按提交」「按需求」等视图怎么分组不影响这条规则。

- **不用整组通过**：不满意的移进废纸篓，通过的那几张组成图文。同组可以分几次通过（单张、所选、其余），都进同一条。
- **等这一组审完才组成**：这一组还有图待生成、生成中或待验收时，设置页显示「等本组 N 张审完」。最后一张通过或移进废纸篓、或生成失败后，立即组成。生成失败的图不拦着这一组。
- **顺序与封面**：按任务编号（审稿页同组里的显示顺序）排，第 1 张是封面。
- **先预览再落库**：先不带 `--apply` 跑一遍 `import-image-sets`（与正式导入同一套检查），通过了才落库。回执里的图文素材 ID 记进批次（`poster_batches.material_id`）供对账。
- **不会多出一条**：请求首次发送前冻结，图文编号是批次 ID；回执丢了、重试、重启后重投，Poster 按同一来源身份回 `duplicate`，不重复建。用户在 Poster 里删了这条图文，回 `deleted`，不复活。
- **组成之后才通过的图**（例如生成失败的那张后来恢复、通过）没法再加进已经建好的图文，照旧散进商品图片库，不另起一条。图文被放弃（「不导入」）后同组再通过的图也一样。
- 带图组图文要求 Poster 的 `import-spec image-sets` 字段表里有 `items[].images`；旧版 Poster 批次停在「需处理」写明「请先更新 Poster」，更新后点「重试」。

Poster 规定同一张图只能用在一条图文里、发过或删过的图不能组图文；若在 GenDesk 组成之前用户已在 Poster 里拿其中的图手工组了图文，预检会拒收，批次停在「需处理」并带着 Poster 的原话。

## 库位

商品之内进哪个库，由作品归属里的 `posterType`（Agent 投单时显式写）或需求名（缺省）决定，交付时按 Poster 当时的图片类型目录解析：

- `封面` / `封面图` → 封面库（`purpose: cover`）；实况图只交静图，封面库不收视频。
- 与 Poster 某个图片类型同名（先比原名，再比去掉末尾「图」字后的名字，须唯一）→ 图片库里的该类型（`typeId`）。
- `未分类`、空、或按需求名对不上 → 图片库，未分类。不按包含或前缀猜。

需求名与类型不同名时由 Agent 写 `organization.posterType`。显式类型对不上：投单时转待确认（「Poster 图片类型对不上」）；交付时（例如类型后来在 Poster 删了）整批停在「需处理」并写明原因，在 Poster 建好同名类型后点「重试」。按需求名对不上只是未分类。已分过类的同一张图，Poster 不会被重投改回去。

按类型导入要求 Poster 声明 `image-type` 能力、商品目录带 `imageTypes`。旧版 Poster 没有类型目录时，按需求名的图照旧进未分类，显式类型的批次报错待更新 Poster 后重试；封面要求 `cover` 能力。

## 文件与恢复

- Poster 直接引用作品目录里的成品（实况则引用 `成品/实况照片` 下的 JPG 与 MOV），不另建副本；已导入的成品请保留原文件。找不到作品成品的旧记录才复制进应用数据目录的 `Poster图片库`。
- 请求使用持久化的来源实例 ID 与作品 UID（图文另以批次 ID 为图文编号），首次发送前冻结请求内容；对方已入库但回执中断时，原样重试不会重复加图、不会重复建图文。
- 失败批次保留原因，设置页可「重试」，应用启动时也会补一轮；不会自动循环重试。
- Poster 回执 `imported / updated / duplicate / deleted` 分别是新增、更新、已存在、用户已删除；已删除的图或图文不会因重试复活。

## 补导历史成品

自动导入关闭期间（或功能上线前）通过的作品从未登记批次。补导只散进图片库，不组图文（事后已分不清哪几张是同一套）。`gendesk poster backfill` 先预演，列出每个款式可补的张数、成品文件已不在的张数和对应商品；`--apply` 只为能对上商品的款式建批（每批最多 50 张）并在后台导入，需先开启自动导入；库位按各作品的需求名照上文规则定。对不上的款式绑定后再跑一次即可；已导入、待处理或选了「不导入」的作品都不会被重复登记。只补静态图：实况配对完成后队列记录即删除，事后无法可靠找回。

## 实现边界

Rust `poster/` 负责设置、商品解析、绑定、批次台账（0046、0050、0055）、图片包分组与结算（`set_key`、`pending_in_set`）、交付与 `backfill` 补导；`intake/ingest.rs` 经 `PosterGate` 在投单时检查归属；`control.rs` 的 `poster.resolve / bind / backfill` 供 CLI 使用；`commands/poster.rs` 提供类型化 IPC；`commands/review.rs` 在验收时登记批次、移进废纸篓后结算这一组，引擎任务生成失败时（`engine/events.rs`）同样结算，`live_photo.rs` 配对完成后回填实况文件并唤醒交付。前端只镜像状态并收集「指定商品」的选择，不判定是否入库。

设置中的 Poster 路径指向已安装应用的 `Contents/MacOS/Poster`，调用不经过 shell。
