> 0.36.0 起，审稿图片统一放入作品根目录的 `成品/生成图片/产品/款式/需求/`，Poster 直接引用这份成品，不再为新作品建立验收批次副本。以下涉及 Poster 待确认、永久批目录的描述仅用于识别和接完旧数据。总开关仍默认关闭；详见 [作品目录整理](作品目录整理.md)。

# Poster 图片接入

GenDesk 适配 Poster 的通用 `poster.images/1` CLI。Poster 不保存明星名单或生成工具约定；其通用接口规范位于 Poster 项目的 `docs/协作规范/图片库CLI接入规范.md`。

## 使用

1. 在设置 › Poster 图片接入开启「审稿后询问导入 Poster」。此功能默认关闭，旧版设置升级后也保持关闭。
2. 通过单张、所选或本组图片的审稿。
3. GenDesk 弹出「是否将本批图片直接导入 Poster」，显示各款张数与对应商品。
4. 点「导入全部 N 张到 Poster」：确认全部目标后，后台静默存放并入库；不拉起 Poster 界面、不碰浏览器、不自动发布。
5. 在 Poster 的对应商品「图片」页选图，新建图文并使用现有发布流程。

总开关关闭时只完成审稿，不询问、不创建新的交接记录或待确认副本，暂停后续后台导入；已经发给 Poster 的本批完成后停止。已导入图片和已有交接记录保留，重新开启后可继续处理。开启总开关也不等于同意每批导入，仍需逐批确认。

「暂不导入」只结束本批交接，不影响已通过的审稿。关闭弹窗是稍后处理，记录保留，可在设置 › Poster 图片接入 › 查看确认重新打开；总开关开启时，重启会再次显示尚未处理的确认。

## 归属

- 查询 Poster 已有商品目录，最终向它传稳定的商品 ID。普通商品目录导入、模糊名称匹配、自动新建商品均不参与这条路径。
- 20 位明星的完整 SKU 别名仅在 GenDesk 适配层定义，首次按完整「姓名日历（2027）」查唯一商品；不从图片文件名或数字 SKU 猜身份。
- 当前「汪苏泷日历／汪苏泷」等旧任务直接兼容。未知 SKU 要在确认窗选目标；SKU 与明星标记互相矛盾时拒绝确认。
- 用户确认后的 `(sku,style) → Poster 商品 ID` 保存在 GenDesk，之后商品改显示名仍使用原 ID。原商品被删除时不自动认领同名新商品。
- 实际图片中的明星是否正确，由人工审稿确认。元数据匹配不能代替看图。

## 文件与恢复

- 功能开启时，审稿通过留一个独立待确认副本，防止批次退休或原交付目录搬走后丢图。这个副本不是导入授权；功能关闭时不创建。
- 只有确认后才将成品放入设置中的永久目录，默认是 GenDesk 应用数据目录下的 `Poster图片库`。用户可选产品项目的成品目录。
- 文件按日期、唯一交接批次与商品分目录；清单中的 ID 决定归属，目录名不参与匹配。已确认批次固定自己的落点，更改设置不搬动已入库图片。
- 请求使用持久化来源实例 ID 与作品原 UID。永久文件、请求与回执均有记录；对方已入库但回执中断时，原样重试不会重复加图。
- 未确认、暂不导入的批次不会进入后台导入队列。功能开启时，已确认失败的批次保留原因，设置页可重试，启动时也会补一轮；关闭时暂停后续处理，不自动循环轰炸接口。
- Poster 返回 `imported/duplicate/deleted`，分别是本次新增、已存在、用户已删除；全部都有逐图回执，后两种不算新增。已删除图片不会由重试复活。
- 仅支持图片；不接入图生视频的通过流程，不导入视频内容。

## 实现边界

Rust 模块 `poster/` 负责设置、完整匹配、持久化选择与交接；`commands/poster.rs` 提供类型化 IPC。新增迁移 `0046_poster_image_handoff.sql` 只修改 GenDesk。

每条作品快照与其待确认记录同事务；审稿通过状态同事务落库。验收过程串行，同一分钟的两次验收有独立目录与清单。前端只镜像状态并收集选择，不能自行判定已入库。

设置中的 Poster 路径指向已安装应用的 `Contents/MacOS/Poster`；接口不经过 shell。旧版应用不支持 JSON 接口时明确提示更新，不静默回退到名字匹配。
