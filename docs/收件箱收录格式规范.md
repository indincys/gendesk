# 收件箱收录格式规范

> 本文档是内容生成端（Claude / Codex Skill）与 GenDesk 收件箱之间的**落盘格式契约**。
> 它可以立即投入使用：即使收录功能尚未开发，先让生成端按本规范落盘积累存量，
> P1 收件箱 watcher 上线后可直接批量收录。
> 配套：`内部图片生产工具_发布与资产管理需求文档.md` §3.6。

## 1. 目录约定

```
<根目录>/收件箱/
├── SF-YD-201/                ← 文件夹名 = SKU 编码（或在软件里登记的「文件夹别名」）
│   ├── 标题_小红书.txt
│   ├── 标题_通用.txt
│   ├── 正文_小红书.txt
│   ├── 图文_抖音.txt          ← 成套文件（标题+正文）
│   ├── img_01.jpg …          ← 根目录散放的图片 → 合并为「一个」默认图集包
│   ├── video_a.mp4           ← 视频 → 每个视频各自一个视频型素材包
│   ├── 开箱图集/              ← 子文件夹 = 一个独立素材包（多图集就多建几个）
│   │   ├── cover.jpg          ← 该图集封面（可选）
│   │   ├── 01_主图.jpg        ← 数字前缀决定图序：01 → img_01
│   │   └── 02_细节.jpg
│   └── 场景图集/
│       ├── 01.jpg
│       └── 02.jpg
├── 已收录/                    ← GenDesk 收录成功后自动归档原 TXT 文件
└── （无法识别 SKU 的文件 → 软件内「待认领」队列，文件保留原位）
```

- 文件名格式：`<类型>.txt`，类型 ∈ {标题, 正文, 图文}。**默认全平台共用**，文件名**不带平台名**
  （每次发布同一套内容发全平台，无需区分）——直接用 `标题.txt` / `正文.txt` / `图文.txt`。
  如确需给某平台单独写，可写成 `<类型>_<平台>.txt`（平台 ∈ {小红书, 抖音, 快手, 视频号, B站, 通用}），
  不带平台名时按「通用」入池，可被全平台任务引用。同名冲突时生成端自行加序号（`标题_2.txt`）。
- **SKU 识别顺序**：**文件头【SKU】 > 文件名前缀 > 所在文件夹名**，任一命中即可；
  按编码都不中时，再按软件里为该 SKU 登记的**文件夹别名**匹配文件夹名（别名允许中文，如
  `A-敖瑞鹏-01` → SKU `NFC-W-01`，在「资产库 → 编辑档案 → 收件箱文件夹别名」里一对一登记）。
  推荐：文件放进 SKU（或别名）文件夹 + 文件头带【SKU】双保险。
- **一个 SKU 多个图集**：在 SKU 文件夹下**再建子文件夹**，每个子文件夹收录为一个独立图集包；
  只有一个图集时，图片直接散放在 SKU 文件夹根目录即可（合并成默认图集）。

## 2. TXT 文件格式

统一使用 UTF-8 编码。文件头字段行以全角括号【】标记，与正文内容之间空一行。

### 2.1 标题文件（`标题_<平台>.txt`）

头部字段后，**一行一条标题**，空行忽略：

```
【SKU】SF-YD-201
【平台】小红书
【类型】标题

小户型也能拥有的云朵感沙发
坐下去的瞬间就不想起来了
新家软装的第一件大件，选它
```

### 2.2 正文文件（`正文_<平台>.txt`）

多条正文之间用单独一行 `====` 分隔（正文内部可自由换行）：

```
【SKU】SF-YD-201
【平台】小红书
【类型】正文

第一条正文……
可以多行。

====

第二条正文……
```

### 2.3 图文套装文件（`图文_<平台>.txt`）

标题与正文成套出现，多套之间用 `====` 分隔。收录时**拆开**分别进标题池与正文池：

```
【SKU】SF-YD-201
【平台】小红书
【类型】图文

【标题】小户型也能拥有的云朵感沙发
【正文】
正文内容……
可以多行。

====

【标题】第二套的标题
【正文】
第二套的正文……
```

### 2.4 【话题】字段（可选，特殊规则）

任何 TXT 的头部可带一行 `【话题】#标签1 #标签2 …`。
话题标签是 **SKU 的固定属性**（不是池）：该 SKU 尚无固定话题时采纳前 5 个；
已有固定话题时**忽略**此行，并在收录报告中提示差异，绝不静默覆盖。

## 3. 素材文件

- 图片 `jpg/jpeg/png/webp`：
  - 直接散放在 **SKU 文件夹根目录** → 合并成**一个**默认图集包；
  - 放进 SKU 文件夹下的**子文件夹** → 每个子文件夹独立成**一个**图集包（一个 SKU 多图集就多建几个子文件夹）。
- 视频 `mp4/mov`：每个文件独立成一个视频型素材包（根目录或子文件夹内均可）。
- **图片顺序**：按文件名排序决定，收录后重命名为 `img_01/img_02…`。想控图序就用数字前缀
  （`01_xxx.jpg`、`02_xxx.jpg`）；收录进软件后也可在资产库里再调整。
- **封面**：图集封面命名为 `cover.jpg`（放在该图集所在目录）；视频封面命名为 `<视频名>_cover.jpg`。
  无封面可留空，发布时平台自动取帧。
- 收录时 GenDesk 会把文件重命名为 ASCII 安全名并移入 `资产库/{SKU 编码}/`（原始文件名存档案，
  即便文件夹用中文别名，落库仍用真实 SKU 编码），生成端无需关心命名规范，
  但**不要用半角特殊字符** `<>:"|?*` 做文件名。

## 4. 落盘与解析的时序约定

- 生成端应**整文件一次性写入**；若工具是流式写盘，先写临时名（如 `.tmp` 后缀）再重命名到位。
- GenDesk 侧防抖：文件大小连续 2 秒稳定才开始解析。
- 解析失败的文件保留原位并进「待人工确认」，不会被删除。

## 5. 给 Claude / Codex Skill 的输出指令模板

把下面这段并入你的文案生成 Skill 的输出要求部分（按需替换占位符）：

```
输出要求：
1. 将结果写入文件，路径为 <根目录>/收件箱/<SKU编码>/<类型>.txt，UTF-8 编码（全平台共用，不带平台名）。
2. 文件头两行依次为：【SKU】<SKU编码>、【类型】标题|正文|图文，随后空一行（【平台】默认省略）。
3. 标题文件：一行一条标题，不加序号、不加引号。
4. 正文文件：多条正文之间用单独一行 ==== 分隔。
5. 图文文件：每套以【标题】一行开头，【正文】起始行后接正文内容；多套之间用单独一行 ==== 分隔。
6. 不要输出任何本格式之外的说明文字或 Markdown 标记。
7. 短视频内容只需生成标题文件；图文内容生成图文文件（或分开的标题文件 + 正文文件）。
8. 话题标签可省略：SKU 若已在软件里批量导入固定话题，文案无需再带【话题】。
```

## 6. 示例校验清单（生成端自检）

- [ ] 文件在正确的 SKU 文件夹内，文件名符合 `<类型>.txt`（默认不带平台名）
- [ ] 文件头【SKU】与文件夹名一致
- [ ] 标题一行一条；正文/图文的多条之间是单独一行 `====`
- [ ] 无 Markdown 代码块、无多余说明文字
- [ ] UTF-8 编码、整文件一次性写入

## 7. SKU 映射批量导入（别名 + 话题）

软件「资产库 → 导入映射」可一次性给多个 SKU 登记**文件夹别名**与**固定话题**。
导入文件为 UTF-8 文本，**每行一个 SKU**，列用 **Tab 或逗号**分隔：

```
<SKU编码>[<分隔><文件夹别名>][<分隔><话题，空格分隔>]
```

示例（`//` 开头为注释行，空列表示不改该项）：

```
// 编码            别名            话题
NFC-W-01,        A-敖瑞鹏-01,     #沙发 #家居 #新品
NFC-W-02,        A-敖瑞鹏-02,     沙发 家居
NFC-W-03,        ,               #客厅 #软装
```

- SKU 编码必须**已存在**（不存在的行跳过并在结果里提示）；
- 别名**一对一唯一**，被别的 SKU 占用则跳过该别名；
- 话题为**显式设置/替换**（去 `#`、去重、最多 5 个）——区别于收件箱 TXT 的「绝不覆盖」，
  这是人工导入的权威动作；
- 导入即时生效，无需重启。
