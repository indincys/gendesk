# 收件箱文案收录格式规范

本文是内容生成端与 GenDesk 之间的落盘契约。图文发布链路以商品为文案归属，以 SKU 为图片归属；收件箱只自动收录 UTF-8 文案 TXT，图片从「图片素材库」导入。

## 1. 目录

```text
<发布根目录>/收件箱/
├── PRODUCT-A/             # 文件夹名 = 商品编码
│   ├── 标题.txt
│   ├── 正文.txt
│   └── 图文.txt
├── 已收录/<日期>/         # 成功收录后自动移入
└── 已丢弃/<日期>/         # 人工丢弃时移入，不物理删除
```

商品识别顺序：文件头 `【商品】` 优先，其次所在文件夹名。识别不到已建档商品时，文件保留原位并进入待认领状态。

文件名类型为 `标题`、`正文` 或 `图文`。可以附加说明后缀，例如 `标题_第二批.txt`；归属平台不写进文件名，商品启用的平台由商品资料和任务单配置决定。

## 2. TXT 格式

文件必须是 UTF-8。头部至少包含商品与类型，头部和内容之间空一行。

### 标题

一行一条，空行忽略。

```text
【商品】PRODUCT-A
【类型】标题

把喜欢的旋律带在身边
今天的包包也挂上本命卡
```

### 正文

每条正文可包含换行，多条之间用单独一行 `====` 分隔。

```text
【商品】PRODUCT-A
【类型】正文

第一条正文第一行。
第一条正文第二行。

====

第二条正文。
```

### 图文

每套包含 `【标题】` 与 `【正文】`，多套之间用 `====`。收录后标题和正文分别进入商品级池。

```text
【商品】PRODUCT-A
【类型】图文

【标题】把喜欢的旋律带在身边
【正文】
正文内容，可以换行。

====

【标题】今天的包包也挂上本命卡
【正文】
第二套正文。
```

### 话题

头部可加 `【话题】#追星好物 #通勤包包`。导入预览会识别这些标签；正式话题匹配仍以文案库中的「SKU 组合专用 > 商品专用 > 通用」三档话题组为准。

## 3. 收录语义

- watcher 等待文件稳定后自动解析，无需在应用内点击。
- 内容哈希先记账再入池；同一内容重复投递不会产生重复文案。
- 成功后原文件移入 `已收录/<日期>/`。
- 无法识别商品或解析失败时原文件不动，并在侧栏徽章与通知中提示。
- `已收录`、`已丢弃` 两个目录不会被再次扫描。

## 4. 给内容生成 Skill 的输出模板

```text
输出要求：
1. 把结果一次性写入 <发布根目录>/收件箱/<商品编码>/<类型>.txt，编码 UTF-8。
2. 文件头依次写【商品】<商品编码>、【类型】标题|正文|图文，随后空一行。
3. 标题文件一行一条，不加序号或引号。
4. 正文文件的多条正文以单独一行 ==== 分隔。
5. 图文文件每套使用【标题】和【正文】，多套以 ==== 分隔。
6. 不输出 Markdown 代码围栏或格式外说明。
```

## 5. 自检

- [ ] 文件位于正确的商品文件夹
- [ ] 文件头是 `【商品】`，不是旧格式 `【SKU】`
- [ ] 类型与正文结构一致
- [ ] 文件为 UTF-8，并通过临时文件重命名或一次性落盘
- [ ] 没有多余 Markdown 标记
