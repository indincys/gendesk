# 收件箱收录格式规范

> 本文档是内容生成端（Claude / Codex Skill）与 GenDesk 收件箱之间的**落盘格式契约**。
> 它可以立即投入使用：即使收录功能尚未开发，先让生成端按本规范落盘积累存量，
> P1 收件箱 watcher 上线后可直接批量收录。
> 配套：`内部图片生产工具_发布与资产管理需求文档.md` §3.6。

## 1. 目录约定

```
<根目录>/收件箱/
├── SF-YD-201/                ← 文件夹名 = SKU 编码
│   ├── 标题_小红书.txt
│   ├── 标题_通用.txt
│   ├── 正文_小红书.txt
│   ├── 图文_抖音.txt          ← 成套文件（标题+正文）
│   ├── img_01.jpg …          ← 外部 AI 生成的图片 → 图集素材包
│   └── video_a.mp4           ← 视频 → 视频型素材包
├── 已收录/                    ← GenDesk 收录成功后自动归档原文件
└── （无法识别 SKU 的文件 → 软件内「待认领」队列，文件保留原位）
```

- 文件名格式：`<类型>_<平台>.txt`，类型 ∈ {标题, 正文, 图文}，
  平台 ∈ {小红书, 抖音, 快手, 视频号, B站, 通用}。同名冲突时生成端自行加序号（`标题_小红书_2.txt`）。
- SKU 识别的冗余顺序：**文件头【SKU】 > 文件名前缀 > 所在文件夹名**，任一命中即可。
  推荐生成端三处都写（文件放进 SKU 文件夹 + 文件头带【SKU】）。

## 2. TXT 文件格式

统一使用 UTF-8 编码。文件头字段行以全角括号【】标记，与正文内容之间空一行。

### 2.1 标题文件（`标题_<平台>.txt`）

头部字段后，**一行一条标题**，空行忽略：

```
【SKU】SF-YD-201
【平台】小红书
【类型】标题

小户型也能拥有的云朵感沙发
坐下去的瞬间就不想起来了
新家软装的第一件大件，选它
```

### 2.2 正文文件（`正文_<平台>.txt`）

多条正文之间用单独一行 `====` 分隔（正文内部可自由换行）：

```
【SKU】SF-YD-201
【平台】小红书
【类型】正文

第一条正文……
可以多行。

====

第二条正文……
```

### 2.3 图文套装文件（`图文_<平台>.txt`）

标题与正文成套出现，多套之间用 `====` 分隔。收录时**拆开**分别进标题池与正文池：

```
【SKU】SF-YD-201
【平台】小红书
【类型】图文

【标题】小户型也能拥有的云朵感沙发
【正文】
正文内容……
可以多行。

====

【标题】第二套的标题
【正文】
第二套的正文……
```

### 2.4 【话题】字段（可选，特殊规则）

任何 TXT 的头部可带一行 `【话题】#标签1 #标签2 …`。
话题标签是 **SKU 的固定属性**（不是池）：该 SKU 尚无固定话题时采纳前 5 个；
已有固定话题时**忽略**此行，并在收录报告中提示差异，绝不静默覆盖。

## 3. 素材文件

- 放入 SKU 文件夹的 `jpg/jpeg/png/webp` 归集为一个图集型素材包（按文件名排序定图片顺序）；
  `mp4/mov` 每个文件独立成一个视频型素材包。
- 同名 `cover.jpg`（或 `<视频名>_cover.jpg`）识别为封面；无封面可留空，发布时平台自动取帧。
- 收录时 GenDesk 会把文件重命名为 ASCII 安全名并移入 `资产库/`（原始文件名存档案），
  生成端无需关心命名规范，但**不要用半角特殊字符** `<>:"|?*` 做文件名。

## 4. 落盘与解析的时序约定

- 生成端应**整文件一次性写入**；若工具是流式写盘，先写临时名（如 `.tmp` 后缀）再重命名到位。
- GenDesk 侧防抖：文件大小连续 2 秒稳定才开始解析。
- 解析失败的文件保留原位并进「待人工确认」，不会被删除。

## 5. 给 Claude / Codex Skill 的输出指令模板

把下面这段并入你的文案生成 Skill 的输出要求部分（按需替换占位符）：

```
输出要求：
1. 将结果写入文件，路径为 <根目录>/收件箱/<SKU编码>/<类型>_<平台>.txt，UTF-8 编码。
2. 文件头三行依次为：【SKU】<SKU编码>、【平台】<平台名>、【类型】标题|正文|图文，随后空一行。
3. 标题文件：一行一条标题，不加序号、不加引号。
4. 正文文件：多条正文之间用单独一行 ==== 分隔。
5. 图文文件：每套以【标题】一行开头，【正文】起始行后接正文内容；多套之间用单独一行 ==== 分隔。
6. 不要输出任何本格式之外的说明文字或 Markdown 标记。
7. 短视频内容只需生成标题文件；图文内容生成图文文件（或分开的标题文件 + 正文文件）。
```

## 6. 示例校验清单（生成端自检）

- [ ] 文件在正确的 SKU 文件夹内，文件名符合 `<类型>_<平台>.txt`
- [ ] 文件头【SKU】与文件夹名一致
- [ ] 标题一行一条；正文/图文的多条之间是单独一行 `====`
- [ ] 无 Markdown 代码块、无多余说明文字
- [ ] UTF-8 编码、整文件一次性写入
